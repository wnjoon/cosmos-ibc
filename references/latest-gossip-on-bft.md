# The latest gossip on BFT consensus

블록체인의 합의 알고리즘 중 Tendermint를 중심으로 한 BFT(Byzantine Fauilt Tolerant, 비잔틴 장애 허용) 합의 알고리즘에 대해 다루고 있는 논문이다. 

> 원문 : [The latest gossip on BFT consensus - Ethan Buchman, Jae Kwon and Zarko Milosevic](https://arxiv.org/abs/1807.04938)

<br>

## 서론

합의(Consensus) 문제는 분산 컴퓨팅에서 핵심적인 문제로, 상태 머신 복제(State Machine Replication, SMR) 방식을 사용한다.

> **상태 머신 복제** <br>
> 분산 네트워크에서 모든 노드가 동일한 상태를 유지하고, 같은 순서로 트랜잭션을 처리하도록 보장하는 방법

Tendermint는 BFT 알고리즘을 기반으로 한다.

<br>

## 모델 및 정의

시스템 내 각 프로세스는 일정한 투표 권한(voting power)를 가지며, 가십 프로토콜(Gossip protocol)을 통해 각 노드가 서로 다른 노드에게 메시지를 전달한다.

> **가십 프로토콜**<br>
> 분산 네트워크에서 노드 간 정보를 효율적으로 전파하기 위한 방법으로, 아래와 같은 특징을 갖는다.
> - 무작위 선택 : 각 노드는 무작위로 다른 노드에게 자신이 알고있는 정보를 전달한다.
> - 점진적 확산 : 초기에는 소수의 노드에게만 정보가 전달되나, 시간이 지나면서 전체 네트워크로 정보가 확산된다.
> - 높은 신뢰도 : 정보가 여러 경로로 전파되기 때문에, 일부 노드가 실패하거나 네트워크에 장애가 있어도 결국 정보는 모든 노드에 확산된다.
> - 확장성 : 노드가 많은 대규모 네트워크 일수록 효율적으로 동작한다.

네트워크는 부분적 동기(partially synchronous)하며, 모든 통신이 신뢰할 수 있게 되는 특정 시간 이후를 GST(Global Stabilization Time)이라고 한다.

<br>

## Tendermint 합의 알고리즘

Tendermint는 라운드 단위로 합의를 진행하며, 각 라운드마다 제안자(proposer)가 존재한다. 제안자는 새로운 블록 또는 값에 대해 제안하고, 다른 노드는 이에 대해 투표한다. 


### 투표를 통한 합의 매커니즘

제안자가 제안한 블록은 다수의 노드에서 prevote, precommit 메시지를 통해 검증되며, 투표권의 3분의 2 이상을 얻으면 해당 블록이 최종적으로 승인된다. n = 3f+1이라고 할 때, n이 시스템의 노드 수이고 최대 f개의 노드는 비잔틴 오류(Byzantine Fault)를 가질 수 있다고 가정한다. 

> **prevote**
> - 제안자가 제안한 블록 또는 값을 다른 노드들이 검토한 후, 이 값을 승인할지의 여부를 담은 메시지
> - 노드가 일정한 수(2f+1)의 다른 노드로부터 prevote 메시지를 수신하면 다음 단계로 이동
> 
> **precommit**
> - 충분한 수의 투표(prevote)가 이루어지면, 노드들은 해당 값에 대해 precommit 메시지를 전송하여 최종 결정을 내림
> - 최소 2f+1개의 precommit 메시지가 모여야 최종 합의 상태로 결정

순서를 간략하게 정리하면,
1. 노드가 제안한 블록 또는 값을 검토한 후, 이를 투표했다는 의미로 prevote 메시지를 전송 
2. 노드가 2f+1개의 prevote 메시지를 받으면, precommit 메시지를 전송
3. 노드가 2f+1개의 precommit 메시지를 받으면, 최종 합의되었다고 판단

### 라운드 로빈 방식의 제안자 선정

Tendermint에서는 라운드 로빈(Round-Robin) 방식으로 제안자를 교체하는데, 투표 권한이 큰 노드일수록 더욱 자주 제안자로 선택된다. 하지만 결국 모든 노드가 차례대로 제안자가 되며, 특정 노드가 계속해서 제안자로 독점되지 않도록 설계되어 있기 때문에 시스템의 공정성과 탈중앙화가 유지된다.

> 예를 들어 A, B, C 노드가 있을 때, A->B->C 순으로 제안자가 되고 이 전체의 과정을 하나의 라운드라고 한다. 라운드가 끝나면 다시 A가 제안자가 된다.

<br>

## 종결 매커니즘(Termination)

2f+1개의 precommit 메시지를 받은 새로운 값(블록)은 잠긴 값(Locked Value)으로 간주된다. 모든 노드가 2f+1개의 precommit을 받을 때까지(합의된 결과가 전파될때까지) 이후 라운드에서도 해당 값을 유지하여 일관성과 신뢰성을 유지하기 위해 사용된다. 

### 잠긴 값

노드들은 이미 잠긴 값이 존재하면, 네트워크의 모든 노드가 동일한 잠긴 값에 대해 합의할 수 있도록 새로운 값이 제안되더라도 해당 잠긴 값을 그대로 유지한다. 하지만 특정 조건에 대해서는 잠긴 값이 변경될 수 있는데, 아래와 같다.
- 더 최근 라운드에서 합의된 값이 2f+1개의 prevote, precommit을 받은 경우, 이전 잠긴 값을 새로운 값으로 변경한다.
- 이전 잠긴 값이 무효화되거나 네트워크 상황에 따라 더 나은 값이 제안된 경우 변경 가능하다.

만약 새로운 블록이 생성된 경우, 특정 노드에 잠긴 값이 없거나 새로운 라운드에서 제안된 값이 기존 값과 상충되지 않으면 새로운 블록이 제안되고 합의에 도달할 수 있다.

<br>

## 결론

Tendermint는 BFT 기반 합의 알고리즘을 기반으로 하며, 고성능 분산 네트워크에서 수백 개 이상의 노드가 서로 신뢰하지 않는 환경에서도 안정적으로 합의에 도달할 수 있도록 한다. Tendermint는 PoS(Proof of Stake) 시스템과 밀접한 연관이 있으며, 각 노드가 네트워크에서의 기여도에 따라 투표권을 갖고 라운드 로빈 방식으로 새로운 값의 제안자가 되는 구조를 갖는다.
